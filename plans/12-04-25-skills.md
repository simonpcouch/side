# Plan: Align Skills with Claude Code Implementation

## Overview

Replace side's skills feature with directory-based skills with bundled resources (scripts/, references/, assets/). Remove the old `.md` file-based skill format.

## Requirements

**Scope**: Core features
- Support directory-based skills with `SKILL.md` + optional bundled resources
- Progressive disclosure: load main skill first, then resources on-demand
- No packaging tooling (directory-based approach)

**Priority Features**:
1. Bundled scripts that can be executed (R and shell)
2. Reference documentation loaded on-demand
3. Asset templates (code/files used in output)

## Architecture

### Skill Format

Directory-based only:
```
skill-name/
├── SKILL.md              # Required: Main instructions
├── scripts/              # Optional: Executable scripts (.R, .sh)
├── references/           # Optional: Additional docs (.md)
└── assets/              # Optional: Templates, resources
```

### Progressive Disclosure Pattern

1. LLM calls `fetch_skill(skill_name)` → receives SKILL.md + resource listing
2. LLM sees available scripts/references/assets and their names
3. LLM calls specific resource tools as needed:
   - `fetch_skill_reference(skill_name, reference)` → load docs
   - `execute_skill_script(skill_name, script)` → run script
   - `get_skill_asset(skill_name, asset)` → read template

## Design Rationale

**Separate tools over single parameterized tool**: Clearer semantics, better type safety, more specific tool descriptions for LLM

**Progressive disclosure**: Prevents context bloat by loading resources only when needed; LLM has explicit control

**Script execution delegation**: Reuse `run_r_code_impl()` and `shell_impl()` for safety checks and consistent error handling

**Directory-based format**: Simpler for R package distribution, easier version control, no compression/extraction needed, supports bundled resources naturally

**User override preserved**: Existing behavior where user skills in `~/.config/side/skills/` override built-in skills continues to work

**Breaking change acceptable**: Skills feature is new enough that forcing migration to the cleaner format is justified
